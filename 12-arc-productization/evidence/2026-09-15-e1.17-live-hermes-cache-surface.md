## Architectural decision

Preserve Hermes core. Build RYZ3N-owned cache/context intelligence around supported extension seams.

Three distinct waste classes remain:

1. **Prefix recomputation** — same stable PRIME/ARC prefix repeatedly prefilled. Hermes already preserves byte stability; exploit provider-side KV/prefix reuse where available and measure cache hits.
2. **Context duplication** — irrelevant/repeated knowledge included in requests. Solve through a provider-independent RYZ3N Context Compiler with versioned context blocks and deterministic ordering.
3. **Duplicate inference** — identical safe work reaching scarce free workers more than once. Solve through narrowly scoped exact-request/in-flight dedup at the LLM execution seam, never by blindly caching agentic/tool-bearing turns.

## Upstream extension proof

Hermes middleware provides behavior-changing `llm_request` and `llm_execution` seams. `llm_execution` may wrap or intentionally short-circuit the provider call while preserving Hermes planner/provider/tool architecture. Observer hooks remain read-only telemetry.

## Safety / correctness invariant

Never reuse a full model response merely because prompts are semantically similar. A response-cache hit is eligible only when the effective provider request is deterministically identical and the request class is explicitly cache-safe. Tool-capable, state-mutating, time-sensitive, retrieval-sensitive, multimodal, or non-deterministic turns fail closed to normal inference unless a stronger proof exists.
