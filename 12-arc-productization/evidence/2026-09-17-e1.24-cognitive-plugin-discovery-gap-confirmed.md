## Important interpretation

This is stronger evidence than the prior hypotheses around:

- middleware-vs-hook manager mismatch;
- turn-ID mismatch;
- middleware request-shape mismatch.

Those paths are now lower priority because the plugin is absent from the active manager entirely in the inspected process.

The Cognitive Connection source itself still contains the intended `register(ctx)` calls for:

- `pre_gateway_dispatch`
- `pre_llm_call`
- `pre_tool_call`
- `transform_llm_output`
- `llm_request` middleware

The remaining engineering question is therefore: **why is the deployed cognitive plugin not being discovered/activated as an active plugin while the cache-controller is?**
