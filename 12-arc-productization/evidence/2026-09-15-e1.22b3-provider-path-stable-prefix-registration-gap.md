# E1.22B.3 — Provider-path stable-prefix registration gap

Date: 2026-09-15
Status: evidence / diagnosis checkpoint
Scope: PRIME Cache Controller v0.1.3, NVIDIA Laguna primary, local Qwen fallback

## Live result

A controlled PRIME request after activating Cache Controller v0.1.3 produced the following telemetry:

- NVIDIA / `poolside/laguna-xs-2.1`
  - `hermes_system_message_char_count`: 32344
  - `provider_leading_prefix_char_count`: 32837
  - `hermes_registered_stable_prefix_found`: false
  - provider attempt failed after ~2363 ms
  - provider-reported cache read: unavailable on failed call
- local Ollama / `qwen3:0.6b` fallback
  - `hermes_system_message_char_count`: 32338
  - `provider_leading_prefix_char_count`: 32831
  - `hermes_registered_stable_prefix_found`: false
  - completed after ~77652 ms
  - provider cache read ratio: 0.0

The visible fallback response returned the requested text wrapped as JSON, so output-discipline quality remains a separate issue from cache measurement.

## Interpretation

This does **not** prove that Hermes' internal `stable` tier is absent.

Earlier source tracing proved that `agent.system_prompt.build_system_prompt_parts()` explicitly constructs `stable`, `context`, and `volatile` tiers and that `build_system_prompt()` stores the stable tier in `_cached_system_prompt_static`.

The present result proves only that Hermes' `prompt_cache_boundary.find_stable_prefix(...)` could not recover a registered stable prefix on these NVIDIA/Ollama request paths at the pre-API observer point.

Therefore the next diagnostic must inspect the narrow source region around `register_stable_prefix(...)` and the condition under which the prompt-cache plan registers that prefix. No prompt mutation or provider change is justified before that gate is understood.

## Architectural consequence

Do not equate:

- provider-facing repeated leading system/request prefix,
- Hermes internal cross-session `stable` tier,
- and a prefix registered for provider-cache machinery.

They are related but distinct measurement domains.

## Reliable Excellence rule

Do not implement compression or cache mutation from an inferred boundary. Prove the active runtime registration gate first, then instrument or optimize the correct layer with reversible changes and live evidence.
