## Defect discovered by shadow mode

The first v0.1 fingerprints both resolved to `44136fa...`, the SHA-256 of an empty JSON object. Root cause: the plugin attempted to derive prompt fingerprints from Hermes' sanitized `request` observer field. Hermes documents the high-sensitivity `request_messages` observer field as the raw provider message sequence, while `request` is a sanitized/size-capped observability view.

Therefore the telemetry transport is GREEN, but fingerprint fidelity is not yet accepted.

## Correction

Cache Controller v0.1.1 changes fingerprint derivation to use `request_messages` transiently in memory only and persist only hashes. It separates:

1. full request fingerprint;
2. history-prefix fingerprint (all wire messages except newest);
3. stable-prefix fingerprint (leading system/developer/non-user wire prefix);
4. fingerprint-source label.

Provider/model/API-mode/tool-count/max-token context is incorporated into the fingerprints to avoid false equality across unlike execution contexts.

Raw `request_messages` remain prohibited from persistence/logging/output.

## Architectural significance
