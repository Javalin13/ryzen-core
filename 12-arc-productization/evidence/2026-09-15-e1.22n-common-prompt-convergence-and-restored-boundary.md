# E1.22N — Common prompt convergence and restored-session boundary

Date: 2026-09-15
Status: GREEN source-boundary proof

## Proven runtime flow

The Hermes gateway converges both fresh and restored sessions into the same active prompt boundary:

- Fresh/new session: `_restore_or_build_system_prompt(...)` calls `agent._build_system_prompt(...)`, then stores the result in `agent._cached_system_prompt`.
- Continuing session: `_restore_or_build_system_prompt(...)` reuses the persisted `stored_prompt` verbatim by assigning it to `agent._cached_system_prompt`.
- `turn_context.py` then reads `agent._cached_system_prompt` as `active_system_prompt`.

This is the shared adoption/convergence seam for PRIME's active system prompt.

## Important semantic constraint

A restored prompt contains frozen historical prompt bytes, but Hermes persists only the full prompt—not the original `stable/context/volatile` tier boundaries. Therefore those old tier boundaries cannot be truthfully recovered from the stored text alone without adding parsing assumptions.

The correct provider-independent measurement strategy is:

1. Preserve the restored active prompt bytes unchanged.
2. At the common convergence seam, generate the canonical current rebuild candidate using `build_system_prompt_parts(...)`.
3. Record only content-free numeric tier metrics (`stable/context/volatile/separators/total`) and comparison booleans against the active prompt.
4. Cache those measurements process-locally by active-prompt fingerprint so a long-lived gateway does not repeat expensive prompt reconstruction on every turn.
5. Never expose or persist raw prompt text through the telemetry layer.

This lets RYZ3N measure the canonical prompt architecture for fresh and restored sessions without rewriting PRIME's active prompt or tying the measurement to any model/provider cache capability.

## Safety / architecture invariants

- No active prompt mutation.
- No routing/provider/model change.
- No Cargo change.
- No raw prompt persistence in RYZ3N telemetry.
- Existing Telegram network repair remains outside this intervention.
- Restored historical bytes remain the runtime truth; rebuild-candidate metrics are explicitly identified as candidate/current canonical composition, not mislabeled as historical persisted boundaries.
