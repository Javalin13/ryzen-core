# E1.22G — Provider-path static tier not materialized

Date: 2026-09-15
Mission: M3/16 — PRIME performance system
Status: GREEN boundary proof; not performance completion

## Live PRIME evidence

With Cache Controller v0.1.4 active and privacy-safe content-free hook instrumentation, the current PRIME request path reported:

- provider-facing Hermes system prompt: 32,344 chars on NVIDIA Laguna
- `hermes_static_system_prefix_available`: false
- `hermes_static_system_prefix_char_count`: null
- `hermes_static_prefix_matches_system_prompt`: false
- `hermes_dynamic_system_tail_char_count`: null
- `hermes_static_share_of_system_prompt`: null
- provider-reported cache read tokens: 0
- provider-reported cache ratio: 0.0

Observed turn behavior:

1. NVIDIA `poolside/laguna-xs-2.1` request completed in ~34.46 s with 20,266 input tokens and 0 cached input tokens.
2. A subsequent NVIDIA attempt failed in ~1.53 s with provider error.
3. Local Qwen fallback then completed in ~114.77 s; its system prompt was ~32,338 chars and no static tier was exposed there either.

## Interpretation

This does **not** mean Hermes lacks stable/context/volatile prompt composition. Earlier source proof established `build_system_prompt_parts()` and `_cached_system_prompt_static` as the authoritative stable-tier architecture.

This live evidence proves that `_cached_system_prompt_static` is not materialized on the current NVIDIA/Ollama request path at the pre-provider observer boundary. The relevant runtime path only ensures/reconstructs the cached static prefix under Hermes prompt-caching capability gating. Therefore downstream request-hook inspection cannot be the provider-independent source of truth for stable-tier sizing.

## Architectural consequence

E1.22 must move one level upstream:

- measure `stable`, `context`, and `volatile` directly at `build_system_prompt_parts()` / system-prompt build time;
- do this independently of provider cache support;
- preserve raw prompt privacy by exporting aggregate counts/hashes only;
- use those builder-tier measurements as the canonical RYZ3N Context Compiler baseline;
- keep provider cache-read telemetry separate as a downstream efficiency metric.

## Reliability / privacy invariants preserved

- no prompt mutation;
- no routing/model/provider change;
- no raw static-prefix content persisted or exposed to generic hooks;
- Cargo remained isolated;
- existing Telegram network repair remained byte-preserved;
- v0.1.4 remained shadow telemetry only.

## Next step

Instrument the authoritative builder seam itself, content-free, before provider capability gating. This is the final measurement step before designing the first actual context-reduction intervention.
