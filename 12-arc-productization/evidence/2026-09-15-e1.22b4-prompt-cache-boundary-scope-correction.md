# E1.22B.4 — Prompt Cache Boundary Scope Correction

Date: 2026-09-15
Status: GREEN source-boundary proof
Scope: PRIME / Hermes prompt-cache semantics

## Finding

The final source inspection disproved the assumption that `agent.prompt_cache_boundary.find_stable_prefix()` exposes Hermes' system-prompt `stable` tier.

`agent/prompt_cache_boundary.py` explicitly documents a different mechanism: builder-declared stable scaffolds for skill/webhook/cron user-message strings, primarily to place Anthropic cache breakpoints at the stable/volatile split inside those constructed messages.

The registry is process-local, bounded, and intended for just-built skill/webhook/cron scaffolds. It is not the authoritative registry for `build_system_prompt_parts()` system-prompt tiers.

Therefore:

- Cache Controller v0.1.3's `hermes_registered_stable_prefix_*` fields are harmless shadow telemetry but are **not authoritative for E1.22 system-prompt tier measurement**.
- A `False` result from `find_stable_prefix(system_text)` is expected on PRIME's NVIDIA/Ollama system-message path and does not mean Hermes lacks a stable system tier.
- The authoritative system-prompt composition remains `build_system_prompt_parts()`:
  - `stable`
  - `context`
  - `volatile`
- `build_system_prompt()` assigns `agent._cached_system_prompt_static = parts["stable"]`; this is the relevant system-prompt stable tier for the E1.22 context/compiler work.

## Live runtime evidence retained

The v0.1.3 live turn still provided useful provider-facing measurements:

- NVIDIA/Laguna system message: 32,344 chars
- provider-leading pre-user prefix: 32,837 chars
- Laguna provider failure after ~2.36 s
- local Qwen fallback system message: 32,338 chars
- Qwen fallback latency ~77.65 s
- provider cache read ratio: 0%

These figures remain valid as provider-facing request measurements, but must not be relabeled as Hermes' internal cross-session `stable` tier.

## Engineering decision

Stop using `prompt_cache_boundary` for E1.22 system-tier inference.

Next intervention must instrument or expose the authoritative builder-level tier sizes (`stable`, `context`, `volatile`) through a supported runtime seam, without mutating prompts or creating a second prompt architecture.

No provider routing, Cargo configuration, or production prompt behavior was changed by this correction.
