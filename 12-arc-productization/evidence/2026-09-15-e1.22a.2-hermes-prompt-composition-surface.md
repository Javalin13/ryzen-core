## Proven runtime architecture

Hermes already owns a first-class system-prompt lifecycle rather than rebuilding an opaque prompt ad hoc on every turn:

- `agent/system_prompt.py::build_system_prompt_parts()` splits the system prompt into a stable band and a volatile band.
- The volatile band explicitly includes the skills index, built-in memory snapshot, USER/profile material, external memory-provider material, timestamp/session/model/provider material, and plugin sections positioned after memory.
- `build_system_prompt()` joins those parts and stores the stable component in `agent._cached_system_prompt_static`.
- `reconstruct_static_prefix()` reconstructs that static cacheable prefix for stored sessions.
- `agent/conversation_loop.py` restores or builds the cached system prompt, persists it to the session database, and replays the system prompt verbatim across turns to preserve cache-prefix stability.
- The conversation loop explicitly states that system-prompt modifications break the cache prefix and therefore reserves the system prompt for Hermes internals while placing turn-varying injected context elsewhere.
- `agent/prompt_cache_boundary.py` exposes stable-prefix registration and lookup.
- `agent/prompt_cache_scope.py` resolves cache scope.
- `agent/prompt_caching.py` exposes `build_prompt_cache_plan()` plus cache-marker application logic.
- `agent/prompt_builder.py` already caches the skills prompt with in-process and disk snapshot layers.

## Architectural consequence

RYZ3N must not create a competing parallel prompt/context framework around Hermes. The correct intervention is surgical and cache-aware:

1. preserve Hermes' existing stable/volatile boundary and per-session cached prompt lifecycle;
2. identify the actual high-volume contributors inside the stable band;
3. classify those contributors as always-on kernel, cache-stable runtime scaffold, conditionally retrievable doctrine, or removable duplication;
4. build any RYZ3N context compilation at the existing composition seam so it preserves byte stability and Hermes cache semantics;
5. keep canonical source doctrine authoritative and never replace it with an unverifiable local hash reference;
6. prove behavior parity and token-pressure reduction in shadow mode before active use.
