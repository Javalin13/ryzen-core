# E1.24 — Cognitive Connection plugin opt-in root cause

Date: 2026-09-17
Status: ROOT CAUSE IDENTIFIED
Master: M3/16 — Cargo ARC GREEN
Current line: E1.24 request-local tool-schema / capacity reduction

## Evidence

The deployed user plugin files for both `ryz3n-cache-controller` and `ryz3n-cognitive-connection` were present under `/home/prime/.hermes/plugins/` and both manifests parsed correctly.

`hermes plugins list` showed:

- `ryz3n-cache-controller` — **enabled** — v0.1.6
- `ryz3n-cognitive-connection` — **not enabled** — v0.3.0

Hermes explicitly reported:

> Plugins are opt-in by default — only 'enabled' plugins load.

This directly explains the earlier runtime observations:

- Plugin Doctor could validate the Cognitive Connection plugin source and registration contract without activating it in the live plugin manager.
- Synthetic runtime probe showed `has_llm_request_middleware = False`, `changed = False`, `trace_count = 0`.
- Active plugin-manager introspection showed no `pre_llm_call` callbacks and no `llm_request` middleware callbacks.
- Live provider telemetry showed unchanged request payload and `middleware_trace_count = 0`.

## Root cause

The Cognitive Connection plugin was **deployed and Doctor-valid but never enabled in Hermes' opt-in plugin registry**.

This was an activation-state defect, not a failure of the v0.3 middleware logic, not a manifest `provides_middleware` issue, not a turn-id mismatch, and not a split plugin-manager instance.

## Required correction

Enable exactly this plugin using Hermes' native plugin command, then restart PRIME only and re-run the synthetic middleware proof before any model call:

`hermes plugins enable ryz3n-cognitive-connection`

Acceptance after restart:

- plugin list shows `ryz3n-cognitive-connection` enabled;
- active manager exposes the plugin's `pre_llm_call` hook;
- active manager exposes `llm_request` middleware;
- synthetic R1 probe removes `tools` and `tool_choice` request-locally;
- only after that, rerun live T3 and compare telemetry payload reduction.

## Portability lesson

For Hermes, plugin presence + Plugin Doctor GREEN does **not** imply runtime activation. Activation is a separate opt-in state that must be recorded and verified.

This becomes part of the Hermes runtime adapter contract for future migrations:

`deploy → validate → enable/activate → restart/reload → introspect live registry → behavioral proof`.

No future model/runtime adapter should treat static validation as equivalent to live activation.
