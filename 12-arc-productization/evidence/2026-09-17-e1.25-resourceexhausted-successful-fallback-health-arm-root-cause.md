# E1.25 ResourceExhausted Successful-Fallback Health Arm Root Cause — 2026-09-17

Status: **ROOT CAUSE CONFIRMED — behavior change not yet applied**

## Scope

This receipt closes the narrow question of why PRIME repeatedly re-probes Laguna on later turns after a successful same-turn fallback to Qwen following `ResourceExhausted`.

## Evidence

A bounded source audit of Hermes found only two assignments to `agent._rate_limited_until`:

1. `agent/chat_completion_helpers.py:2491` — rate-limit/billing/upstream-rate-limit path with exponential backoff beginning at 60 seconds.
2. `agent/chat_completion_helpers.py:2508` — fallback-chain-exhausted path, using `_FALLBACK_EXHAUSTED_COOLDOWN_S`.

The successful fallback activation path begins at `try_activate_fallback()` line ~2513, selects the next fallback entry, resolves its provider/model/client and proceeds to activate the fallback. No assignment to `_rate_limited_until` exists in that successful-fallback path.

Therefore, when primary Laguna fails with `ResourceExhausted` and fallback Qwen succeeds, the session can enter fallback successfully **without arming cross-turn primary-health cooldown state**.

`restore_primary_runtime()` correctly checks `_rate_limited_until` and stays on fallback while that deadline is active, but in this path there is no deadline to enforce.

## Root cause

The active Hermes implementation distinguishes:

- explicit `rate_limit` / `billing` / `upstream_rate_limit` reasons, which arm cross-turn cooldown;
- fallback-chain exhaustion, which arms a short cooldown;
- successful fallback after other provider failures, which can complete the turn without arming cross-turn primary-health state.

The observed PRIME behavior is therefore explained by a missing health-state arm on successful fallback for the `ResourceExhausted` class, not by a broken restore gate and not merely by a cooldown constant that is too short.

## Smallest correct direction

Reuse Hermes' existing `_rate_limited_until` / `restore_primary_runtime()` mechanism. Do not create a parallel RYZ3N circuit unless necessary.

The next proof must identify the exact `FailoverReason` assigned to the Laguna `ResourceExhausted` event, then apply a bounded cooldown policy for that reason when the primary provider successfully switches to fallback.

Required properties:

1. same-turn fallback remains single-attempt and fast;
2. later turns during cooldown remain on the healthy fallback directly;
3. primary probing resumes automatically after bounded cooldown/reset criteria;
4. no permanent pinning to fallback;
5. no provider-specific hardcoding into RYZ3N cognition;
6. the policy remains portable as provider-health adapter logic.

## Stop rule

Do not alter cooldown durations or add circuit code until the exact `FailoverReason` mapping for the observed `ResourceExhausted` exception is confirmed.

## Architectural implication

RYZ3N owns the health-policy contract; Hermes is the current runtime adapter. The reusable contract is:

`primary failure classification → health-state arm → bounded fallback residency → automatic recovery probe → verified restoration`.
