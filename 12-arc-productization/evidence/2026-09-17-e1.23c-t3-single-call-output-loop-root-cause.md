# E1.23C — T3 Single-Call Output Loop Root Cause

Date: 2026-09-17
Master: M3/16 — Cargo ARC GREEN
Status: ROOT CAUSE CLASSIFIED — fix not yet deployed

## Live T3 test

Founder asked PRIME, without tools, whether it could know the current Brussels weather with certainty and what would be required to verify it.

Observed behavior:

- semantic answer was correct;
- PRIME respected the explicit no-tools instruction;
- no `/think` leakage was visible;
- output repeated the same answer dozens of times across multiple Telegram chunks;
- the turn took roughly 136 seconds end-to-end at the provider call level.

## Telemetry proof

Current-session telemetry for the T3 turn identifies one request:

- model: `poolside/laguna-xs-2.1`
- provider: `nvidia`
- `api_call_count: 1`
- pre-request observed at `2026-09-17T13:19:52.513074+00:00`
- post-request observed at `2026-09-17T13:22:08.738989+00:00`
- latency: `136225.911 ms`
- output tokens: `2051`
- input tokens: `20398`
- status: success
- no fallback event for this turn
- no second/third API call for this turn

This proves the repetition was produced inside a single successful model response. It was not caused by Hermes replaying multiple requests or by fallback recursion.

## Architectural implication

The current `ryz3n-cognitive-connection` v0.1.0 only structurally governs explicit `Reply exactly:` turns. Ordinary/no-tool turns fall through to the default lane and therefore have no bounded-response/stop-discipline guard in the Cognitive Connection layer.

The next correction should therefore remain inside the Cognitive Connection abstraction and should not reopen model hunting, Telegram behavior, cache work, or broad Hermes redesign.

Priority:

1. add a generic bounded no-tool/direct lane for explicit no-tool requests;
2. enforce stop/repetition discipline for that lane;
3. keep semantic completeness while preventing runaway repetition;
4. rerun T3;
5. only then continue T4–T6.
