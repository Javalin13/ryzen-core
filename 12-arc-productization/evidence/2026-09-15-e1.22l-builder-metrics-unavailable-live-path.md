# E1.22L — Builder Metrics Unavailable on Current Live Telegram Path

Date: 2026-09-15
Mission: M3/16 Cargo GREEN — PRIME performance substrate
Status: NEGATIVE-PATH PROOF / CONTINUE

## Live result
After deploying and activating Cache Controller v0.1.5 and Hermes provider-independent builder-tier instrumentation, the current PRIME Telegram session emitted telemetry with `builder_tier_metrics_available: false` on all observed NVIDIA/Laguna and local-Qwen API attempts.

The expected content-free builder metrics were therefore absent:
- builder_stable_char_count: null
- builder_context_char_count: null
- builder_volatile_char_count: null
- builder_total_char_count: null
- builder tier shares: null

## Interpretation
This does **not** prove that Hermes lacks stable/context/volatile prompt tiers. Source inspection already proved `build_system_prompt_parts()` returns those three canonical tiers and `build_system_prompt()` joins them.

It proves only that the current long-lived Telegram session/request path did not leave `_ryz3n_prompt_tier_metrics` populated on the live agent before the `pre_api_request` hook fired. Therefore a prompt adoption/restore/cached path is bypassing the newly instrumented `build_system_prompt()` assignment for this session, or the metrics are otherwise not being retained on that path.

## Engineering consequence
Do not optimize prompt tiers from guessed/null measurements. Trace the alternate `_cached_system_prompt` adoption/restoration path and instrument the shared provider-independent point used by both fresh-build and restored-session execution.

## Concurrent acceptance failures observed
The same controlled turn remained performance/correctness RED: unnecessary multi-iteration/tool behavior, a tool-call error, Laguna provider failure, local Qwen fallback, and excessive end-to-end latency. These are active acceptance failures but are not to be conflated with the builder-metrics boundary investigation.

## Reliability rule
Negative measurements are evidence. Do not reinterpret null telemetry as success and do not change prompt content until the authoritative tier boundary is observed on the actual live path.
