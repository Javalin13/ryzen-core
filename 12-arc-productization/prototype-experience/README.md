## Purpose

Every real ARC prototype must accumulate its lived experience so the final ARC UX/system is designed from evidence rather than imagination.

This folder is the canonical cross-pilot experience layer for:

- user friction;
- confusion and misunderstood behavior;
- successful interaction patterns;
- recurring user requests;
- onboarding issues;
- trust/privacy concerns;
- missing controls;
- memory/context failures;
- notification/timing issues;
- language/interface needs;
- reliability/recovery incidents;
- support interventions;
- moments where the ARC created clear value;
- features users ignore or do not understand.

## Core doctrine

> **No prototype experience is allowed to disappear into chat history, memory or anecdote. Reusable experience must enter the backlog and become an input to the final ARC UX/system.**

## Evidence flow

`real ARC usage → raw experience → classified backlog item → pattern across pilots → product requirement → UX/system design candidate → implementation → validation in later pilots`

## Files

- `EXPERIENCE-BACKLOG.md` — cross-pilot backlog and prioritization rules.
- `TEMPLATE.md` — standard record for one meaningful experience/incident/need.
- `UX-FEED-CONTRACT.md` — defines when/how accumulated experience becomes input to the final ARC UX/system.

Pilot-specific raw evidence remains in each pilot folder when appropriate, but reusable learnings must be promoted here.

## Capture rule

Capture an item when it is at least one of:

1. repeated;
2. high-friction;
3. high-value;
4. safety/privacy/reliability relevant;
5. commercially relevant;
6. likely reusable across more than one ARC;
7. a direct user request that may affect the product contract.

Do not promote private customer content itself. Generalize the pattern and preserve confidentiality.
