# OMEGA / FACTORY Visual Identity Discovery Amendment

Status: **Founder-directed additive runtime-governance amendment**  
Date: 2026-09-11  
Parent standards:
- `OMEGA-ARC-FACTORY-STEWARDSHIP-STANDARD.md`
- `ARC-VISUAL-IDENTITY-HUMANOID-FAMILY-STANDARD.md`
- `ARC-FORM-AURA-AND-TRANSFER-RESET-STANDARD.md`

## Decision

Every autonomous ARC's detailed visual identity belongs to that ARC's own source repository.

PRIME, OMEGA and FACTORY must be able to discover that visual truth without becoming a second unrestricted asset/history store.

## Required ARC-level discovery fields

For every ARC created or materially re-formed after this amendment, the ARC instance/registration metadata and PRIME supervision mirror should expose, where applicable:

- `visual_identity_record` — pointer to the ARC-owned human-readable visual contract;
- `visual_identity_metadata` — pointer to the ARC-owned machine-readable visual record;
- `canonical_profile_asset` — pointer to the currently accepted primary portrait/profile image;
- `visual_family_standard` — canonical RYZ3N visual-family standard/version;
- `archetype` — e.g. humanoid synthetic intelligence;
- `presentation` — ARC-specific presentation such as male/female/neutral where Founder/Owner intent defines it;
- `form_version`;
- `founder_owner_approved` state;
- `maturity_aura_rendering_status` so form styling is never confused with earned maturity.

FACTORY may store these pointers and safe metadata. It should not copy the entire image-generation transcript, private ARC context or large binary assets into PRIME.

## ARC birth / Factory behavior

Future Factory creation must initialize the ARC visual package defined by `ARC-VISUAL-IDENTITY-HUMANOID-FAMILY-STANDARD.md` during birth.

The Factory may create visual candidates, but candidate generation must inherit the canonical family and ARC-specific metadata rather than use a blank/free-form robot prompt.

The accepted primary visual form requires Founder/Owner approval and is then committed to the ARC repository.

OMEGA verifies that the ARC instance record, FACTORY entry and PRIME mirror all point to the same accepted visual identity package.

## Material feedback / revision rule

When Founder/Owner feedback materially changes the ARC's visual contract — for example mascot → humanoid, female → male presentation, a domain cue added/removed, or a family-alignment correction — that decision must be captured in the ARC-owned visual history.

OMEGA records only the resulting form version/pointers and material lifecycle event when needed.

## Aura boundary

Visual identity metadata never grants maturity.

An ARC profile can use domain/accent styling before maturity acceptance, but any explicitly represented maturity aura remains evidence-derived under the existing form/aura standard.

> **The ARC repository remembers the face. OMEGA keeps the pointers coherent. FACTORY remembers material form history. PRIME can always find the current truth.**
