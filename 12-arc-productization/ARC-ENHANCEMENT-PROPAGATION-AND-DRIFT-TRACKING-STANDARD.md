# ARC Enhancement Propagation & Drift Tracking Standard

Status: Founder-directed implementation standard  
Effective: 2026-09-11  
Constitution/Canon impact: none

## Purpose

Material ARC architecture improvements must not live only in one chat, one VPS edit, one ARC instance, or one operator's memory.

Every material enhancement is propagated to the durable layer that owns that kind of truth and is then tracked for adoption/drift across the ARC portfolio.

> **Enhancement discovered once; durable lesson propagated once; each ARC records its own truthful adoption state.**

This standard is operational only. Constitution/Canons remain Founder-protected and are never amended by implication.

## 1. Propagation layers

For every material enhancement, classify and update the applicable layers:

1. **RYZ3N reusable architecture** — `Javalin13/ryzen-core` owns universal doctrine, standards, schemas and reusable operating contracts.
2. **Golden/Factory inheritance** — VONDA Golden Blueprint/additive amendments or Factory production standards capture reusable implementation patterns for future ARCs where appropriate.
3. **ARC authoritative source** — the affected ARC repository owns its detailed source, instance state, bridge, runtime manifests, tests and evidence.
4. **PRIME / OMEGA / FACTORY bounded truth** — portfolio registries/mirrors store lifecycle, routing, seal, maturity and adoption pointers, never unrestricted private ARC payload.
5. **Runtime/recovery truth** — versioned runtime source, manifests, deployment/recovery scripts and clean-room evidence must match the authoritative ARC source where applicable.
6. **Evidence / CI** — audits, workflows and bridge reports prove the enhancement is active rather than merely documented.

A layer that is genuinely not applicable must be recorded as `N/A` rather than silently omitted.

## 2. Material enhancement test

Treat a change as material when it changes one or more of:

- ARC authority or repository ownership;
- identity/binding/privacy model;
- runtime isolation or recovery;
- bridge/routing/orchestration behavior;
- autonomy/concurrency model;
- Factory birth/provisioning contract;
- OMEGA/FACTORY stewardship expectations;
- maturity/lifecycle evidence rules;
- cross-ARC interaction or source boundaries;
- reusable CI/audit invariants;
- client-facing implementation-abstraction/release behavior;
- ARC system-prompt depth that controls public identity/role behavior;
- capacity-telemetry/privacy architecture;
- clean-room reconstruction or loaded-module certification gates.

Routine content edits, normal domain work and one-off business records do not require portfolio propagation unless they reveal a reusable architectural lesson.

## 3. Required propagation record

For each material enhancement, OMEGA keeps a privacy-safe ledger entry containing:

- enhancement ID/name;
- source event / originating ARC or standard;
- reusable RYZ3N standard pointer;
- Golden/Factory inheritance pointer when applicable;
- per-ARC adoption state;
- PRIME/OMEGA/FACTORY reconciliation state;
- CI/evidence pointer when applicable;
- open drift/blockers;
- explicit Canon impact (`none` unless Founder separately authorizes a Canon request).

## 4. Adoption states

Use truthful states such as:

- `defined_reusable` — reusable rule exists upstream;
- `inherited_pre_runtime` — encoded before live runtime exists;
- `implemented_unverified` — source exists but live/evidence proof pending;
- `GREEN_applied` — implementation and required evidence pass;
- `N/A` — not applicable to that ARC/lifecycle stage;
- `DRIFT` — required propagation or implementation has diverged;
- `superseded` — replaced by a newer approved operational rule.

A working local/VPS implementation that has not been committed/pushed into the authoritative ARC source remains `implemented_unverified` for canonical source purposes even if a live test passes.

## 5. Drift rule

A material enhancement is not considered fully propagated until the authoritative reusable standard and all applicable current-instance/portfolio surfaces agree.

OMEGA should flag drift when, for example:

- an ARC runs a newer runtime behavior than its repository source;
- an ARC instance state contradicts OMEGA/FACTORY;
- a reusable lesson exists only in one ARC and has not been upstreamed;
- an operational ARC is still routed through PRIME after ARC-primary transition;
- `consume` can read a stale local checkout without a source-freshness preflight;
- autonomy, hermetic seal or maturity are conflated;
- future ARC birth templates do not inherit a proven reusable control;
- a shared platform persona/pairing mechanism is visible on a client-facing ARC channel;
- a depth-enhancement works in the live profile but the new config/plugins are missing from the authoritative runtime-source manifest;
- capacity telemetry stores customer/private content rather than privacy-safe signals.

## 6. Source-freshness and concurrent work

Before applying an enhancement to an active ARC or shared portfolio file, re-read the newest authoritative HEAD.

Concurrent workstreams must not be blindly overwritten. The applicable rule is:

`newest authoritative truth → reconcile surgically → preserve unrelated newer state → record propagation evidence`

This is especially important while PRIME is actively building another ARC (for example NARC) while Lux/Cargo are evolving Cargo-specific architecture.

Local unpushed commits and remote newer commits must be reconciled explicitly; neither may be silently discarded or force-pushed over the other.

## 7. No false background guarantee

Tracking is durable and event-driven through ARC `consume`, PRIME execution reports, Lux syncs, OMEGA/FACTORY reconciliation and CI evidence.

No component should claim that a change was propagated merely because it was discussed. A Git commit/evidence pointer or an explicit pending/drift state is required.

## 8. Current foundational enhancements

The current ledger should track at minimum:

- authoritative ARC source-boundary ownership;
- hermetic operations and isolation;
- continuous own-repo autonomy + safe concurrent writer;
- keyed multi-candidate onboarding and exact binding;
- versioned runtime source + clean-room recovery;
- ARC-primary direct bridge with PRIME portfolio oversight;
- source-freshness preflight before `consume`;
- separation of autonomy, hermetic seal and maturity/aura;
- **VONDA-class four-boundary ARC depth baseline**: identity + task store + Owner onboarding + capacity telemetry;
- **deep ARC-specific system prompt** rather than generic platform fallback;
- **client-facing ARC-only release gate** that explicitly rejects platform pairing/persona leakage;
- **three-plane privacy-safe capacity telemetry**: raw ARC-local events → protected rollups → steward aggregate;
- **clean-room module/config/audit proof + live loaded-module proof** after material runtime-depth changes.

Canonical depth template:

`12-arc-productization/ARC-DEPTH-ENHANCEMENT-VONDA-CLASS-TEMPLATE.md`

Reusable NARC incident/reference lesson:

`12-arc-productization/NARC-DEPTH-ENHANCEMENT-REFERENCE-2026-09-11.md`

## 9. VONDA-class depth propagation rule

When a new ARC or an existing ARC adopts the VONDA-class depth baseline, propagation is not complete until all applicable layers agree on:

1. the intended four runtime boundaries/plugins/modules;
2. ARC-specific deep configuration/system prompt;
3. runtime-source manifest coverage;
4. hermetic/source audit state;
5. clean-room reconstruction result;
6. live loaded-module state;
7. clean unbound client-facing result;
8. capacity-telemetry privacy contract;
9. PRIME/OMEGA/FACTORY adoption classification.

A local/VPS-only enhancement may be reported as a successful engineering checkpoint, but it does not become canonical `GREEN_applied` until the authoritative ARC repository has the exact source/manifest and the portfolio mirrors reconcile to that committed evidence.

## Founder invariant

> **If an ARC teaches RYZ3N something reusable, that lesson must become durable architecture; if architecture changes an ARC, the ARC and portfolio records must show the truthful adoption state.**
