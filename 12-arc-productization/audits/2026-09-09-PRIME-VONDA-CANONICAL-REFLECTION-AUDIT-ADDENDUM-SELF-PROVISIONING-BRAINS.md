## Founder clarification incorporated

Specialist Brains are not meant to be fully designed in advance by PRIME or by a central catalogue.

The ARC itself develops and creates the specialist reasoning units it needs in order to fulfil the wishes, intent and outcomes of its Maker/Owner, subject to the ARC framing and RYZ3N constitutional constraints.

For VONDA this means:

`Laetitia/Founder intent → VONDA ARC → self-provisioned specialist Brain → Agents → Execution`

When a stable specialization emerges, VONDA creates a durable GitHub folder under:

`VONDA-Corporation/arc/BRAINS/<SPECIALIZATION>/`

Example only:

`arc/BRAINS/COACHING/`

The example is not a pre-created mandatory Brain.

## Audit impact

This clarification improves canonical fit because it restores the intended hierarchy more faithfully:

- ARC retains framing and is responsible for the reasoning units beneath it;
- Brains emerge as domain-specific reasoning units inside that ARC;
- Agents execute under Brain authority;
- execution generates evidence that flows back upward;
- PRIME/Hermes remains operational infrastructure/stewardship rather than becoming the designer of every client Brain.

## Updated strengths

1. **Emergent specialization over speculative taxonomy** — closely matches the canon's structural roles without architecture inflation.
2. **Owner intent remains upstream** — Brain creation serves the Maker/Owner instead of becoming self-directed ecosystem strategy.
3. **Durable continuity** — Brain creation produces GitHub artifacts and therefore does not exist only in runtime memory.
4. **ARC autonomy** — the ARC becomes capable of developing its own reasoning topology while remaining constitutionally bounded.
5. **PRIME stays adjacent** — BRAIN STEWARD registers, verifies and supervises but does not become a super-Brain or ARC owner.
6. **Future RYZ3N inheritance remains clean** — native RYZ3N can later assume Brain lifecycle governance without changing the ARC/Brain ontology.

## Remaining weaknesses / engineering gaps

The policy is now aligned, but the following are not yet fully implemented runtime reality:

- automatic detection of when repeated reasoning should become a candidate Brain;
- a safe Brain scaffold/provision function that creates the GitHub folder/contracts idempotently;
- machine-readable Brain registry updates;
- automatic PRIME BRAIN STEWARD mirror registration;
- runtime routing from ARC to newly created Brain specialization;
- Agent contract generation/registration beneath a Brain;
- deprecation/supersession automation;
- Brain interconnect runtime envelope;
- complete end-to-end test of `need → Brain creation → reasoning → Agent → execution → evidence → upward convergence`.

These remain build targets, not claims of current reality.

## Attention points

- Do not convert every new task into a Brain.
- Brain creation must be evidence-driven or explicitly Owner/Founder-directed.
- Client-facing UX should remain one coherent ARC; internal Brain taxonomy should not burden the owner.
- Brain creation must not grant new external permissions/secrets by itself.
- Cross-client private memory stays prohibited.
- Material architectural/security/scope changes escalate; routine safe Brain lifecycle changes should not overload the PRIME↔Lux bridge.
- PRIME's mirror is supervision metadata, not a private-data fork.
