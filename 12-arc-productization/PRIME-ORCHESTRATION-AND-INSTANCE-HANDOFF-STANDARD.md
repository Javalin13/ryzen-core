# PRIME Orchestration & Instance Handoff Standard

Status: Founder-directed active prototype standard  
Created: 2026-09-11  
Updated: 2026-09-11 — hermetic production gate integrated  
Constitutional status: non-canon implementation standard; protected Constitution/Canons unchanged

## Founder decision

**PRIME remains the active supervisor, director and orchestrator of the complete ARC production and lifecycle flow during the prototype era.**

PRIME does not surrender orchestration when OMEGA, FACTORY, BRAIN STEWARD or an ARC performs specialized work. Those instances/functions operate under bounded responsibility and report state/evidence back into PRIME's orchestration loop.

Canonical ontology remains:

`Creator → RYZ3N → ARCs → Brains → Agents → Execution`

PRIME, OMEGA, FACTORY and BRAIN STEWARD are prototype control/stewardship infrastructure around that ontology; they are not new canonical tiers.

This standard does not rewrite or amend protected Constitution/Canon files. Any Canon change requires a separate explicit Founder request and approval.

## Control principle

> **PRIME orchestrates the cycle. OMEGA stewards ARC population. FACTORY records lifecycle truth. BRAIN STEWARD governs Brain coherence. Each ARC owns its own bounded domain execution. Hermetic boundaries block progression when source/runtime/identity/write/recovery closure is incomplete.**

No instance may silently absorb another instance's authority or private runtime boundary.

## Responsibility matrix

### PRIME — supervisor / director / orchestrator

PRIME owns the operational control loop. PRIME:

- receives Founder-authorized creation/lifecycle intent;
- opens and tracks the ARC production cycle;
- directs OMEGA to classify/reserve/register ARC-level facts;
- directs FACTORY lifecycle record creation/update through the approved stewardship path;
- directs repository provisioning through approved infrastructure capability;
- coordinates ARC package manufacture from the versioned Factory contract;
- coordinates BRAIN STEWARD only when Brain-level lifecycle facts exist;
- coordinates runtime provisioning, channel setup, health/isolation testing and recovery checks;
- ensures the ARC inherits a hermetic contract before production runtime;
- ensures all required ARC-specific runtime components have authoritative versioned source;
- ensures unknown identities fail closed and pending candidates are keyed separately;
- ensures explicit exact-candidate binding rather than latest-candidate shortcuts;
- ensures client-facing users interact with the ARC while PRIME remains backend infrastructure;
- ensures repository-autonomy state is explicit;
- if autonomy is enabled, ensures safe shared-writer optimistic-concurrency is installed and enforced;
- ensures source-driven recovery and clean-room reconstruction evidence before hermetic GREEN;
- blocks progression when any required instance reports contradiction/failure;
- keeps stage ordering coherent;
- receives status/evidence from all participating instances;
- reports material progress, blockers and decisions to Founder;
- preserves Founder approval gates and external-side-effect boundaries.

PRIME must not replace the ARC's detailed domain source, invent maturity, ingest unrestricted customer-private memory, silently bind ambiguous candidates, or let orchestration become unlimited authority.

### OMEGA — ARC-population steward under PRIME

OMEGA performs delegated ARC-level stewardship. OMEGA:

- reserves/checks stable `arc_id`;
- classifies source-boundary type;
- checks source uniqueness and rejects dual-active truth;
- maintains ARC registry coherence;
- tracks ownership/lifecycle/form/maturity pointers;
- tracks hermetic-seal state separately from maturity;
- validates ARC-level registration completeness;
- validates presence/coherence of source/runtime/autonomy/recovery pointers required by the hermetic standard;
- detects ARC-level drift/contradiction;
- escalates cross-ARC runtime coupling, candidate ambiguity, unversioned runtime source, unsafe autonomous writes or recovery dependence on another ARC;
- reports findings and blockers to PRIME;
- coordinates bounded ARC-level updates with FACTORY.

OMEGA does not independently direct the whole Factory cycle, provision runtime by itself, own customer domain reasoning, or overrule PRIME/Founder intent.

### FACTORY — lifecycle/provenance register under PRIME stewardship

FACTORY is the durable production/lifecycle record. FACTORY:

- records genesis before repository creation where applicable;
- records source creation/designation and provenance;
- records production-stage transitions;
- records runtime/binding/evidence status;
- records hermetic-seal status and evidence pointers;
- records autonomy state and safe-writer status where applicable;
- records reset/transfer/migration/history;
- preserves historical truth rather than silently rewriting provenance.

FACTORY does not reason, orchestrate, create Brains, grant permissions or execute customer work.

### BRAIN STEWARD — Brain-level coherence under PRIME

BRAIN STEWARD is invoked when an ARC contains/creates/changes Brains. It:

- validates Brain ownership by exactly one ARC;
- validates reasoning scope/non-scope;
- validates Agent authority/delegation boundaries;
- validates Brain lifecycle/interconnect/evidence;
- reports ARC-level implications to OMEGA and PRIME.

BRAIN STEWARD does not register ARC population, run FACTORY, or invent Brains without ARC/Owner need.

### ARC instance — bounded domain owner/executor

The ARC:

- owns its detailed source/configuration inside its authoritative repository;
- serves its Owner/domain;
- manages its own permitted memory/tasks/domain competence;
- creates/uses Brains according to canonical lifecycle rules;
- executes only within granted permissions/capacity;
- uses only its own private runtime boundary for identity/authorization unless an explicit interoperability contract authorizes otherwise;
- if own-repository autonomy is granted, writes only its own repository through the approved safe-writer protocol;
- produces evidence/status upward without leaking unrestricted private payload.

The ARC does not rewrite RYZ3N canon, mutate other ARC repositories, read another ARC's private runtime as a shortcut, self-promote maturity/aura, force-push shared history, or commandeer PRIME/OMEGA/FACTORY authority.

## Orchestrated Factory flow

Every stage is orchestrated by PRIME:

`Founder intent`  
`→ PRIME opens production cycle`  
`→ PRIME directs OMEGA identity/source classification`  
`→ PRIME confirms FACTORY genesis record`  
`→ PRIME directs repository create/designate capability`  
`→ PRIME directs Factory package + hermetic contract manufacture`  
`→ PRIME requests OMEGA registration validation`  
`→ PRIME confirms FACTORY active/pre-runtime record`  
`→ PRIME maintains supervision mirror`  
`→ PRIME coordinates isolated runtime/channel/capacity provisioning`  
`→ PRIME closes runtime-source + keyed onboarding + recovery/write-safety gates`  
`→ PRIME coordinates explicit exact-candidate Owner binding`  
`→ ARC performs real first-run/useful work`  
`→ PRIME gathers evidence from ARC + OMEGA + BRAIN STEWARD as applicable`  
`→ PRIME evaluates lifecycle + hermetic + privacy + maturity gates separately`  
`→ truthful lifecycle/hermetic/maturity state recorded`

The phrase “OMEGA/FACTORY handles creation” must never be interpreted as PRIME stepping out of the loop. PRIME delegates specialized responsibilities while retaining orchestration.

## Hermetic progression gate

PRIME must not report an ARC as hermetically GREEN until evidence proves:

- one authoritative repository/source boundary;
- isolated ARC runtime/profile/state/secrets;
- no direct read/write dependency on another ARC's private runtime for identity/authorization;
- complete runtime-source manifest;
- every required ARC-specific runtime component stored in the authoritative repository;
- unknown identities fail closed;
- pending candidates are keyed independently;
- explicit binding selects the exact candidate + role;
- user-facing ARC boundary hides PRIME/runtime/binding scaffolding;
- autonomy state is explicit;
- safe shared-writer transaction exists and is enforced if autonomy is enabled;
- autonomous force push/history rewrite is impossible by policy/process;
- clean-room source reconstruction succeeds;
- controlled restart preserves valid state and isolation;
- CI/audit enforcement remains GREEN.

Hermetic GREEN and maturity/aura are separate. PRIME must not infer one from the other.

## Shared-writer orchestration rule

If PRIME/operator and an ARC may both write the ARC's authoritative repository, PRIME must treat repository writes as optimistic-concurrency transactions.

Required safe transaction:

`fetch/sync → base SHA → bounded change → audit → re-fetch → abort on divergence → commit → re-fetch → non-force push → verify remote SHA → verify CI → report receipt`

PRIME must not instruct an autonomous ARC to:

- force push;
- use `--force-with-lease`;
- destructively reset shared remote history;
- silently auto-rebase concurrent PRIME work by default;
- push through a detected remote movement.

If platform branch protection is unavailable, PRIME must preserve equivalent fail-safe process through the safe writer, CI and OMEGA drift detection.

## Handoff rule

Every handoff must specify:

- sending instance;
- receiving instance/function;
- exact requested action;
- authority boundary;
- expected artifact/result;
- blocking conditions;
- hermetic impact/state where relevant;
- evidence/checkpoint pointer;
- return path to PRIME.

A handoff is incomplete until PRIME receives the expected result or an explicit blocker.

A runtime-sensitive handoff is additionally incomplete when required source was changed only on the VPS and not promoted to authoritative source.

## No silent progression

PRIME must not advance a production stage merely because a file or process exists. Examples:

- repo exists ≠ source package complete;
- source package exists ≠ OMEGA registered;
- OMEGA registered ≠ runtime live;
- runtime live ≠ runtime source complete;
- runtime source complete ≠ hermetic GREEN;
- one pending candidate file ≠ safe multi-user onboarding;
- Owner bound ≠ V1 earned;
- hermetic GREEN ≠ V1 earned;
- profile image exists ≠ aura earned;
- successful push ≠ safe shared-writer completion until remote + CI are verified.

## Telegram / control surfaces

Founder Telegram or another authorized PRIME control surface can initiate or inspect the cycle. Telegram is a surface; PRIME is the orchestrator. OMEGA/FACTORY/BRAIN STEWARD remain backend specialized functions unless explicitly exposed for operational diagnostics.

Customer/co-founder ARC channels are different: the user interacts with the ARC. PRIME's pairing/binding/provisioning machinery remains backend infrastructure and should not be exposed as the user experience.

## Future native RYZ3N

Native RYZ3N is expected to absorb these proven orchestration/stewardship contracts later. The current PRIME-centered implementation is prototype-era operational architecture, not a permanent new canonical tier.

Future inheritance includes hermetic source/runtime closure, safe binding, safe shared-repository writes, recovery verification and evidence-separated maturity.

## Founder invariant

> **PRIME supervises, directs and orchestrates the whole cycle. Specialized instances perform their bounded responsibilities and report back. No stage is complete while its source/runtime/identity/write/recovery boundary is silently open.**
