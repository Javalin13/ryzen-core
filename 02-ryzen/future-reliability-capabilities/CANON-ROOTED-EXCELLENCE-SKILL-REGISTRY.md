# Canon-Rooted Excellence Skill Registry

**Status:** Strategic Reliability Skill Overlay / Real-World Operating Specification  
**Authority:** NONE — this document creates no Brain, layer, tier, sovereignty, or parallel architecture  
**Canonical roots:** Canonical Genesis Architecture + canonical ARC architecture + Reliable Excellence doctrine  
**Scope:** Canon Layers 0–25 and every explicitly named Brain/Steward nested within them

---

## 1. Purpose

The Canon defines **who owns what**. This registry defines:

> **What skills, operating behavior, evidence and boundaries make each existing Canon owner exceptionally competent and reliably trustworthy at its assigned responsibility?**

This is a quality overlay, not architecture.

It preserves the Canon law:

**Shared awareness → Distinct responsibility → Unified coherence → Non-duplicated authority**

And the Reliable Excellence red thread:

**Know-how → High-Quality Execution → Verification → Proven Reliability → Reliable Excellence**

Missing material evidence remains **UNPROVEN**.

A skill is not a Brain. A metric is not authority. A profile is not Canon. A model output is not system truth.

---

## 2. Universal excellence substrate

Every cognitive owner should inherit these skills in proportion to its responsibility:

- heuristic reasoning without heuristic overreach;
- epistemic-state discipline and calibrated uncertainty;
- temporal coherence and evidence freshness;
- causal/root-cause reasoning;
- contradiction and inconsistency detection;
- provenance awareness;
- falsification and inference-to-evidence conversion;
- change-impact reasoning;
- graceful degradation;
- bounded escalation judgment;
- observability literacy;
- outcome verification;
- cognitive degradation/disagreement detection;
- recovery and state-reconciliation awareness;
- security, privacy and authority-boundary awareness;
- resource/cost/latency discipline;
- recursive verification;
- anti-theater discipline: reported success must match operational reality.

These are reusable **skills beneath Canon owners**, not independent authorities.

### Non-canonical design-quality lens

When refining any profile, prefer structural simplicity without truth loss, whole-system flow, formal rigor, signal/noise discipline, closed-loop feedback, identity integration, reusable patterns, interdisciplinary synthesis and restraint before adding complexity.

## B. Completion truth states

Where relevant, layers should distinguish:

**not started → ready → in progress → blocked → attempted → partially completed → completed-unverified → verified-complete → failed → unknown**
